2. Factory Method and Facade

Implemented by Boranbai Dauletkali

Factory Method (creational)

PaymentCreator declares the factory method createPayment(). CardPaymentCreator, CashPaymentCreator and QrPaymentCreator each decide which concrete PaymentMethod to instantiate. PaymentMethodFactory holds the creators in a map keyed by PaymentType and hands out the right one, so the checkout code never uses new CardPayment() and never contains an if/else over payment types. The shared validation (null or negative amount) lives once in AbstractPaymentMethod.pay() and each payment only implements doPay(), which keeps the code DRY. Adding Apple Pay means one new payment class and one new creator.






Facade (structural)


KioskFacade.checkout(order, paymentType, promotion) hides the whole checkout flow behind a single call: check stock, calculate the price, create the payment method, process it, write the audit record, reduce stock and publish events. The facade depends on two interfaces defined in its own subsystem, StockService and PaymentGateway, so the inventory or the payment backend can be replaced without touching the facade (Dependency Inversion). PaymentProcessor only processes the payment; the audit entry is written by TransactionLog, so each class has one responsibility. A declined payment returns before stock or observers are touched.
