4. Demo and verification

Run with sh build.sh (JDK 17+). Main executes six scenarios and throws an exception if a result is wrong: four sales succeed for a total of $1,828.80, a card payment above the $1,000 limit is declined, an order for more headphones than are in stock is rejected, both failures leave the stock unchanged, and an unsubscribed dashboard no longer receives sales.

5. Clean code and SOLID

SRP. InventoryService manages stock, PriceCalculator only calculates a price, PaymentProcessor only processes a payment and TransactionLog only records it.

OCP. A new promotion, payment type, product add-on or event listener is a new class; no existing class changes.

LSP. BasicProduct and every decorator can replace each other as a Product; all payment methods keep the contract of PaymentMethod.

ISP. The interfaces are small: KioskListener, PricingStrategy, PaymentCreator, StockService and PaymentGateway each declare only what their clients use.

DIP. The facade depends on the StockService and PaymentGateway interfaces, pricing depends on PricingStrategy and payment depends on PaymentMethod. PriceCalculator, PaymentMethodFactory and EventPublisher are still injected as concrete classes, which is a known limitation.

KISS and DRY. Money is a BigDecimal rounded in one place; payment validation is written once in AbstractPaymentMethod; quantities are grouped by SKU once and reused for the stock check and the stock update.

Conclusion

The kiosk integrates six design patterns (Builder, Factory Method, Decorator, Facade, Observer and Strategy) in one coherent checkout flow, and every pattern is exercised by the demo. Each pattern sits in its own package, and the facade keeps the client code to a single call. The patterns made the later changes cheap: money type, stateless pricing, typed observers and a third decorator were added without touching unrelated packages.

Further work

Persist the stock and the transaction log between runs, introduce interfaces for the remaining concrete collaborators of the facade, add a touchscreen user interface and connect a real payment provider. Unit tests could replace the checks in Main.
